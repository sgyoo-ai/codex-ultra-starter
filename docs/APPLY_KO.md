# 새 프로젝트 적용과 복원

이 문서는 대상 프로젝트에 설정을 적용할 때의 절차야. 저장소 게시·다운로드만으로 다른 프로젝트의 설정이 바뀌지는 않아. 실제 새 프로젝트의 설정 로드와 실행은 해당 프로젝트에서 확인해야 해.

## 적용 전

1. 대상 프로젝트 루트와 가져올 템플릿 태그/커밋을 확인해.
2. 대상 `AGENTS.md`, `.codex/config.toml`, 같은 이름의 역할 파일을 확인해. 사용자 전역 설정은 필요한 충돌 항목만 확인하고 비밀값을 출력하지 마.
3. 원본 바이트·해시와 새 파일이 없던 상태를 대상 프로젝트의 로컬 백업에 보관해. 백업은 Git에 넣지 않아.
4. 대상 앱·세션이 지원하는 역할 형식·모델·추론 강도를 확인해. 이번 작업과 무관한 사용자 전역 모델·권한·서비스를 바꾸지 않아.

## 비어 있는 새 프로젝트

- 템플릿의 `AGENTS.md`를 프로젝트 루트에, `.codex`를 같은 루트에 복사해.
- 프로젝트 소개·실행/검증 절차·보존 대상·공유 자원·핵심 계약을 해당 프로젝트 문서와 AGENTS.md에 보충해.
- 템플릿의 README는 설정 사용 설명서야. 새 프로젝트 자체의 소개로 사용할 필요는 없어.

## 기존 설정이 있는 프로젝트

- AGENTS.md는 기존 규칙을 보존하며 공통 분담 규칙을 병합해. 기존 원문을 통째로 대체하지 마.
- config.toml은 `[agents]`의 4개 항목만 충돌을 검토해 병합해. 같은 테이블을 중복 선언하거나 MCP·권한·개인 설정을 덮어쓰지 않아.
- 역할 파일은 동명 역할을 비교해 병합해. 다른 이름의 역할 파일은 보존해.
- 이름만 같고 이전 정의가 남아 있다면 실제 로드 여부를 확인해. 사용자 전역·프로젝트 설정을 무조건 중복 설치하지 마.

## 확인 순서

1. TOML 문법과 8개 역할의 이름·모델·강도, 열린 서브 한도 5를 확인해.
2. 대상 루트·프로젝트 신뢰·설정 우선순위와 실제 로드를 확인해. 계정이나 관리자 정책으로 지원이 제한될 수 있어.
3. [호환성 안내](V2_COMPATIBILITY_KO.md)에 따라 실제 생성 도구의 인자를 확인해.
4. 첫 필요한 실제 작업에서 역할 지침·모델·강도·컨텍스트 전달과 결과를 확인해. 확인용 모델/서브 호출을 별도로 만들지 않아.
5. 문법 검사·설정 로드·도구 정의·실제 실행의 결과를 구분해 프로젝트 문서에 남겨.

## 업데이트

- 검증한 태그나 커밋을 기준으로 가져오고 현재 프로젝트의 보완 내용과 비교해.
- 모델·강도·권한·핵심 계약의 변경은 일반 문구 업데이트와 구분해 검토해.
- 매번 기존 파일과 신규 파일의 부재 상태를 백업해. Git 버전만으로 로컬 미커밋 상태까지 복원된다고 가정하지 마.

## 복원

- 이후 변경이 없다면 백업한 파일을 복원하고 이번에 새로 만든 파일만 제거해.
- 적용 전 `.codex`가 없고 이후 추가 설정도 없다면 이번에 만든 프로젝트 `.codex`를 제거할 수 있어. 기존 설정이 있었다면 전체 폴더 대신 파일별로 복원해.
- 이후 다른 수정이 있다면 차이를 비교해 보존하고 이번 변경만 되돌려.
- 사용자 홈의 `.codex`는 복원 대상이 아니야. 과거 대화·진행 중인 서브의 이력과 모델 설정은 파일 복원만으로 사라지지 않아. 필요한 서브를 정리하고 새 프로젝트 대화에서 다시 확인해.
